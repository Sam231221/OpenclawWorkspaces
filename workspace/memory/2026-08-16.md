- Investigated Mr. Sam's report that the YouTube daily digest arrived four
  times and not at the expected 6am.
- Root cause: the systemd digest sender fired at 2026-08-16T05:00:09Z
  because the timer was configured for `06:00 Europe/London` while the
  workspace/user timezone is UTC. Telegram delivery was unhealthy and each run
  allowed two OpenClaw CLI send attempts; systemd then retried the whole
  service once after 15 minutes, producing four outbound Telegram send attempts.
- Fixed duplicate risk by changing `scripts/send_youtube_digest.mjs` default
  send attempts from 2 to 1 and removing `Restart=on-failure` from
  `openclaw-youtube-linkedin-digest.service`.
- Fixed schedule drift by changing the live and source timer to
  `OnCalendar=*-*-* 06:00:00 UTC` and disabling `Persistent` catch-up so missed
  or reloaded timers do not send late.
- Updated `docs/youtube_linkedin_workflow.md`,
  `docs/youtube_linkedin_workflow_deep_dive.md`,
  `scripts/youtube_linkedin_workflow_metadata.mjs`, and synced
  `state/youtube_linkedin_workflow.json`.
- Note: restarting the timer while `Persistent=true` was still active caused one
  catch-up digest send at 2026-08-16T19:02:08Z, Telegram message ID 227. After
  that, `Persistent=false` was installed and verified; next run is
  2026-08-17T06:00:00Z.
